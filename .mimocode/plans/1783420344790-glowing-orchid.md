## 🔴 GAP 1: No Orchestrator Wires the Full Pipeline

**What exists**: Each stage is an independent agent. The `CodeGenRuntime.build_sdlc_graph()` defines the DAG and the `GraphScheduler` drives it.

**What's missing**: There is no single entry point that takes a specification, calls `/plan` to get an IntentIR, feeds it to `/develop` to build the SDLC DAG, and executes the full pipeline end-to-end. The DAG exists but there is no API route or CLI command that triggers the entire sequence from specification to release.

**What's needed**: A `POST /api/v1/agentos/sdlc` route (or `soma sdlc <spec-file>` CLI command) that:
1. Reads a specification file
2. Calls `compile_intent()` to produce IntentIR
3. Calls `CodeGenRuntime.build_sdlc_graph(intent_ir)` to build the DAG
4. Runs `GraphScheduler.tick_all()` to completion
5. Returns the release artifact

**Files to create**: `src/monkey_brain/api/routes/sdlc.py` (new route) or `packages/soma-cli/soma/cli/main.py` (new CLI command)

## 🔴 GAP 2: No Release Artifact Creation on GitHub

**What exists**: `PullRequestAgent` creates PRs. `DeploymentAgent` deploys locally.

**What's missing**: After merge, there is no agent that creates a GitHub Release, tags the commit, or publishes to PyPI. The diagram shows "Release" as the terminal node but the codebase only has local deployment + Docker image building.

**What's needed**: A `ReleaseAgent` that, post-merge:
1. Tags the merged commit (`git tag v{version}`)
2. Pushes the tag (`git push origin v{version}`)
3. Creates a GitHub Release via API (`POST /repos/{owner}/{repo}/releases`)
4. Optionally publishes to PyPI

**Files to create**: `packages/broca/broca/agents/release_agent.py`

---

## 🔴 GAP 3: Checkpoint Store Is In-Memory Only

**What exists**: `Checkpoint` dataclass with HMAC signing, `CheckpointStore` class.

**What's missing**: `CheckpointStore` stores checkpoints in a Python dict. If the process crashes, all checkpoints are lost. The code has a `TODO` comment acknowledging this needs MongoDB backing.

**What's needed**: A `MongoCheckpointStore` that serializes checkpoints to MongoDB, enabling crash recovery and cross-process checkpoint sharing.

**Files to modify**: `src/monkey_brain/kernel/process/checkpoint.py` (add `MongoCheckpointStore` class)

---

## 🔴 GAP 4: CapabilityScheduler Is a Stub

**What exists**: `CapabilityScheduler` class exists but its `schedule()` method returns placeholder dicts.

**What's missing**: The scheduler that decides which capabilities to run, in what order, with what resource allocation is not implemented. The `GraphScheduler` handles DAG-level scheduling, but fine-grained capability scheduling (which LLM provider, which Docker resource, which retry policy) is stubbed.

**What's needed**: Implement `CapabilityScheduler.schedule()` to query `CapabilityRegistry`, check provider availability, estimate cost/reward via `ICapability.estimate_cost()` / `estimate_reward()`, and return execution plans.

**Files to modify**: `packages/cerebellum/cerebellum/capabilities/scheduler.py`
